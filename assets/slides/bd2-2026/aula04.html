Parser

Os mesmos 13 tokens, em duas ordens. Só o primeiro é válido:

CREATE TABLE aluno (id INT, nome CHAR(20))
CREATE TABLE aluno (id INT nome, CHAR(20))

O tokenizador olha um token de cada vez, sem lembrar o que veio antes. Para ele, os dois são iguais. Quem olha a ordem é o parser.

O parser confere a ordem contra a gramática e monta a estrutura: que coluna tem que tipo, que valor pertence a que WHERE.

A gramática do minidb

comando := ( create | insert | select ) [ ; ]
create  := CREATE TABLE nome ( coluna { , coluna } )
coluna  := nome INT  |  nome CHAR ( número )
insert  := INSERT INTO nome VALUES ( valor { , valor } )
select  := SELECT ( * | nome { , nome } ) FROM nome [ WHERE nome = valor ]
valor   := número  |  texto
  • [ ] é opcional, { } repete zero ou mais vezes, | é escolha
  • Sem junção, sem ORDER BY, sem agregação, sem subconsulta, sem OR. É o suficiente para o critério de pronto
  • CHAR(n) ocupa sempre n bytes. O registro continua de tamanho fixo, como no M1

Como escrever um parser

regra
create := CREATE TABLE nome ( coluna { , coluna } )

vira
função create():
    espera CREATE
    espera TABLE
    tabela ← espera NOME
    espera (
    colunas ← [ coluna() ]
    enquanto aceita ,
        acrescenta coluna() em colunas
    espera )
    devolve {op: CREATE, tabela, colunas}
  • 1. Uma função por regra da gramática
  • 2. Duas operações sobre a lista de tokens: espera consome o token ou dá erro de sintaxe; aceita consome só se casar
  • 3. Traduza a regra pedaço por pedaço: obrigatório vira espera, [ ] vira se aceita, { } vira enquanto aceita, | vira se/senão olhando o próximo token
  • 4. Regra que cita outra regra chama a função dela: create chama coluna
  • 5. Cada função devolve um pedaço da árvore. No fim, espera FIM: se sobrou token, é erro

A árvore sintática

  • Os tokens viraram estrutura: o parser sabe que 20 é o tamanho de nome, e não uma coluna
  • CREATE, TABLE, parênteses e vírgulas somem. Serviram para o parser decidir, e acabou
{"op": "CREATE", "tabela": "aluno",
 "colunas": [("id", "INT", 4), ("matricula", "INT", 4), ("nome", "CHAR", 20)]}

A árvore é o que o parser devolve: cada função de regra monta o seu pedaço, e a de cima junta tudo. Em Python, um dicionário basta. Em C, uma struct.

A lição do módulo

O parser decide o que é comando e o que é dado. Concatenar string apaga essa fronteira, e é por isso que a injeção existe.

Quem implementou um parser não esquece mais essa distinção. É o motivo de segurança ser ensinada aqui, e não numa aula separada.

O tokenizador em código

def tokeniza(sql):
    tokens, i = [], 0
    while i < len(sql):
        c = sql[i]
        if c.isspace(): i += 1
        elif c.isalpha():                               # palavra reservada ou nome
            j = i
            while j < len(sql) and (sql[j].isalnum() or sql[j] == "_"): j += 1
            p = sql[i:j]
            tokens.append(("PALAVRA", p.upper()) if p.upper() in PALAVRAS else ("NOME", p))
            i = j
        elif c.isdigit(): ...                           # mesmo laço, com isdigit
        elif c == "'":                                  # texto vai até a próxima aspa
            j = sql.find("'", i + 1)
            if j < 0: raise ErroLexico(f"aspas sem fechamento na posição {i}")
            tokens.append(("TEXTO", sql[i + 1:j]))
            i = j + 1
        elif c in "(),;*=":
            tokens.append(("SIMBOLO", c)); i += 1
        else: raise ErroLexico(f"caractere inesperado {c!r} na posição {i}")
    return tokens + [("FIM", None)]

Descida recursiva: uma função por regra

def create(self):
    self.espera("PALAVRA", "CREATE")
    self.espera("PALAVRA", "TABLE")
    tabela = self.espera("NOME")
    self.espera("SIMBOLO", "(")
    colunas = [self.coluna()]
    while self.aceita("SIMBOLO", ","):
        colunas.append(self.coluna())
    self.espera("SIMBOLO", ")")
    return {"op": "CREATE", "tabela": tabela, "colunas": colunas}

def coluna(self):
    nome = self.espera("NOME")
    if self.aceita("PALAVRA", "INT"):
        return (nome, "INT", 4)
    self.espera("PALAVRA", "CHAR")
    self.espera("SIMBOLO", "(")
    n = self.espera("NUMERO")
    self.espera("SIMBOLO", ")")
    return (nome, "CHAR", n)
  • Palavra obrigatória vira espera
  • | e [ ] viram if
  • { } vira while
  • Regra que chama regra vira chamada de função: create chama coluna

espera consome o token ou levanta erro de sintaxe. aceita consome só se casar, e diz se casou. As duas estão no próximo slide, e o select logo depois.

O esqueleto do M4: o parser

class Parser:
    def __init__(self, tokens):
        self.tokens, self.i = tokens, 0
    def olha(self):
        return self.tokens[self.i]
    def aceita(self, tipo, valor):
        if self.tokens[self.i] == (tipo, valor):
            self.i += 1
            return True
        return False
    def espera(self, tipo, valor=None):
        t, v = self.tokens[self.i]
        if t != tipo or (valor is not None and v != valor):
            raise ErroSintatico(f"esperava {valor or tipo}, veio {v!r}")
        self.i += 1
        return v
    def valor(self):
        t, v = self.olha()
        if t in ("NUMERO", "TEXTO"):
            self.i += 1
            return v
        raise ErroSintatico(f"esperava valor, veio {v!r}")
Apêndice

O esqueleto do M4: o comando

def comando(self):
    _, v = self.olha()
    if v == "CREATE":   arvore = self.create()
    elif v == "INSERT": arvore = self.insert()     # mesmo molde do create, com valor
    elif v == "SELECT": arvore = self.select()
    else: raise ErroSintatico(f"comando desconhecido {v!r}")
    self.aceita("SIMBOLO", ";")
    self.espera("FIM")                            # sobrou token? é erro
    return arvore

def analisa(sql):                                 # o que o resto do minidb chama
    return Parser(tokeniza(sql)).comando()

O esqueleto do M4: o SELECT

def select(self):
    self.espera("PALAVRA", "SELECT")
    if self.aceita("SIMBOLO", "*"):
        colunas = ["*"]
    else:
        colunas = [self.espera("NOME")]
        while self.aceita("SIMBOLO", ","):
            colunas.append(self.espera("NOME"))
    self.espera("PALAVRA", "FROM")
    tabela = self.espera("NOME")
    where = None
    if self.aceita("PALAVRA", "WHERE"):
        coluna = self.espera("NOME")
        self.espera("SIMBOLO", "=")
        where = (coluna, self.valor())
    return {"op": "SELECT", "colunas": colunas, "tabela": tabela, "where": where}

O parser já aceita o WHERE. Quem vai executá-lo é o M5.

O esqueleto do M4: o INSERT

def insert(self):
    self.espera("PALAVRA", "INSERT")
    self.espera("PALAVRA", "INTO")
    tabela = self.espera("NOME")
    self.espera("PALAVRA", "VALUES")
    self.espera("SIMBOLO", "(")
    valores = [self.valor()]
    while self.aceita("SIMBOLO", ","):
        valores.append(self.valor())
    self.espera("SIMBOLO", ")")
    return {"op": "INSERT", "tabela": tabela, "valores": valores}

O mesmo molde do create, com valor no lugar de coluna. O parser não confere se o valor bate com o tipo da coluna: isso é semântica, e precisa do catálogo.
