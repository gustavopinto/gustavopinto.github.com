Quem já roda SELECT * FROM aluno?

Ninguém. Até aqui o minidb é uma biblioteca: quem chama insere e le_pagina é o código de teste de vocês, e não uma consulta.

Hoje o minidb aprende a ler. Ao fim do M4, ele recebe SQL pela entrada padrão, responde, e o primeiro SELECT roda de verdade.

O caminho de uma consulta

1

Tokenizador

Quebra o texto em tokens: palavra reservada, nome, número, texto, símbolo

2

Parser

Confere a ordem dos tokens contra a gramática e monta a árvore sintática

3

Análise semântica

A tabela existe? A coluna existe? O tipo bate? Quem responde é o catálogo

4

Execução

No M4, um if por comando, direto sobre a árvore. No M5, operadores

Cada etapa tem o seu tipo de erro. Misturar as três primeiras é o defeito mais comum deste módulo.

Tokenizador

SELECT nome FROM aluno WHERE id = 42
SELECTpalavranomenomeFROMpalavraalunonomeWHEREpalavraidnome=símbolo42númeroFIMfim
  • Espaço some, e palavra reservada vira maiúscula: select e SELECT dão o mesmo token
  • O token leva tipo e valor. O 42 já sai como número, e não como o texto "42"
  • O tokenizador não sabe se a ordem faz sentido. FROM SELECT 42 passa sem reclamar

O tokenizador em código

def tokeniza(sql):
    tokens, i = [], 0
    while i < len(sql):
        c = sql[i]
        if c.isspace(): i += 1
        elif c.isalpha():                               # palavra reservada ou nome
            j = i
            while j < len(sql) and (sql[j].isalnum() or sql[j] == "_"): j += 1
            p = sql[i:j]
            tokens.append(("PALAVRA", p.upper()) if p.upper() in PALAVRAS else ("NOME", p))
            i = j
        elif c.isdigit(): ...                           # mesmo laço, com isdigit
        elif c == "'":                                  # texto vai até a próxima aspa
            j = sql.find("'", i + 1)
            if j < 0: raise ErroLexico(f"aspas sem fechamento na posição {i}")
            tokens.append(("TEXTO", sql[i + 1:j]))
            i = j + 1
        elif c in "(),;*=":
            tokens.append(("SIMBOLO", c)); i += 1
        else: raise ErroLexico(f"caractere inesperado {c!r} na posição {i}")
    return tokens + [("FIM", None)]

A gramática do minidb

comando := ( create | insert | select ) [ ; ]
create  := CREATE TABLE nome ( coluna { , coluna } )
coluna  := nome INT  |  nome CHAR ( número )
insert  := INSERT INTO nome VALUES ( valor { , valor } )
select  := SELECT ( * | nome { , nome } ) FROM nome [ WHERE nome = valor ]
valor   := número  |  texto
  • [ ] é opcional, { } repete zero ou mais vezes, | é escolha
  • Sem junção, sem ORDER BY, sem agregação, sem subconsulta, sem OR. É o suficiente para o critério de pronto
  • CHAR(n) ocupa sempre n bytes. O registro continua de tamanho fixo, como no M1

A árvore sintática

SELECT nome FROM aluno WHERE id = 42

  • Os tokens viraram estrutura: o parser sabe que 42 é o valor do WHERE, e não uma coluna
  • FROM, WHERE e os parênteses não aparecem. Serviram para o parser decidir, e acabou
{"op": "SELECT", "colunas": ["nome"], "tabela": "aluno", "where": ("id", 42)}

Em Python, um dicionário basta. Em C, uma struct com um campo de tipo.

Descida recursiva: uma função por regra

def select(self):
    self.espera("PALAVRA", "SELECT")
    if self.aceita("SIMBOLO", "*"):
        colunas = ["*"]
    else:
        colunas = [self.espera("NOME")]
        while self.aceita("SIMBOLO", ","):
            colunas.append(self.espera("NOME"))
    self.espera("PALAVRA", "FROM")
    tabela = self.espera("NOME")
    where = None
    if self.aceita("PALAVRA", "WHERE"):
        coluna = self.espera("NOME")
        self.espera("SIMBOLO", "=")
        where = (coluna, self.valor())
    return {"op": "SELECT", "colunas": colunas,
            "tabela": tabela, "where": where}
  • Palavra obrigatória vira espera
  • | e [ ] viram if
  • { } vira while
  • Regra que chama regra vira chamada de função, como self.valor()

espera consome o token ou levanta erro de sintaxe. aceita consome só se casar, e diz se casou. As duas, inteiras, estão no apêndice.

O catálogo

Catálogo é o conjunto de tabelas em que o banco guarda a descrição das outras tabelas.

  • Quais tabelas existem, com quais colunas e tipos, onde começam, e quais índices têm
  • No PostgreSQL: pg_class, pg_attribute, pg_index, consultáveis com SQL

O SQLite vai além: guarda o próprio texto do CREATE TABLE, e analisa de novo toda vez que abre o arquivo.

sqlite> SELECT name, rootpage, sql FROM sqlite_schema;
aluno|2|CREATE TABLE aluno (id INT, nome TEXT, nota INT)

O catálogo do minidb é uma tabela

registro do catálogo, 240 bytes, 17 por página

nome      CHAR(32)    "aluno"
primeira  INT         2                       // primeira página da tabela
raiz      INT         0                       // raiz do índice, 0 se não há (M5)
sql       CHAR(200)   "CREATE TABLE aluno (id INT, matricula INT, nome CHAR(20))"
  • Guardamos o texto, como o SQLite. Ao abrir o arquivo, o mesmo parser lê o texto e devolve as colunas
  • Nada de formato novo: o catálogo usa as páginas do M1, o cache do M2 e a mesma serialização de registro
  • CREATE TABLE é só um INSERT nessa tabela, mais uma página nova para a tabela criada

O ovo e a galinha

O catálogo descreve todas as tabelas. Quem descreve o catálogo?

ESQUEMA_CATALOGO = Esquema([("nome", "CHAR", 32), ("primeira", "INT", 4),
                            ("raiz", "INT", 4), ("sql", "CHAR", 200)])
PAGINA_CATALOGO = 1                                # fixa, combinada no código

class Catalogo:
    def __init__(self, cache):
        self.tabelas = {}
        for nome, primeira, raiz, sql in varre(cache, PAGINA_CATALOGO, ESQUEMA_CATALOGO):
            colunas = analisa(sql)["colunas"]       # o parser, de novo
            self.tabelas[nome] = (primeira, Esquema(colunas))

Só duas coisas ficam no código: o esquema do próprio catálogo, e a página onde ele começa. Todo o resto vem do disco.

Várias tabelas no mesmo arquivo

dados.db
+-----------+-----------+-----------+-----------+-----------+
| página 0  | página 1  | página 2  | página 3  | página 4  |
| metadados | catálogo  | aluno     | curso     | aluno     |
+-----------+-----------+-----------+-----------+-----------+
                              |                       ^
                              +--- próxima = 4 -------+          // a 4 aponta para 0: fim

O heap do M1 supunha uma tabela só. Agora cada página sabe qual é a próxima da mesma tabela, e o cabeçalho de 16 bytes ainda tem espaço para isso:

byte 0-1    n_slots ocupados
byte 2-3    tamanho do registro
byte 4-7    número desta página
byte 8-11   próxima página da mesma tabela     // novo. 0 é o fim, porque a 0 nunca é dado
byte 12-15  reservado                          // o M7 ainda cabe aqui

Varrer uma tabela

def varre(cache, primeira, esquema):
    n = primeira
    while n != 0:
        buf = cache.fixa(n)
        try:
            n_slots, tam, _, proxima = struct.unpack_from("<HHII", buf, 0)
            for s in range(n_slots):
                yield esquema.desserializa(buf, TAM_CABECALHO + s * tam)
        finally:
            cache.solta(n)
        n = proxima
  • É a varredura do M1, seguindo a corrente de páginas em vez de ler o arquivo inteiro
  • O mesmo fixa e solta do M2, com try/finally
  • Serve para o catálogo e para qualquer tabela. Muda só o esquema

Executar sem executor

def executa(sql, catalogo, cache):
    arvore = analisa(sql)                                   # tokenizador e parser
    if arvore["op"] == "CREATE":
        catalogo.cria(arvore["tabela"], arvore["colunas"], sql)
        return "OK"
    primeira, esquema = catalogo.busca(arvore["tabela"])    # semântica: a tabela existe?
    if arvore["op"] == "INSERT":
        confere_tipos(esquema, arvore["valores"])           # semântica: os tipos batem?
        insere(cache, primeira, esquema, arvore["valores"])
        return "OK 1"
    linhas = ["|".join(map(str, r)) for r in varre(cache, primeira, esquema)]
    n = len(linhas)
    return "\n".join(linhas + [f"({n} linha{'s' * (n != 1)})"])

É um interpretador de árvore: olha o op e faz. Funciona para SELECT *. No M5 isso vira uma pilha de operadores, e é ali que entram o WHERE e o índice.

Onde isso entra no minidb

SELECT * FROM aluno;

M4  tokenizador          5 tokens, mais o FIM
M4  parser               {"op": "SELECT", "colunas": ["*"], "tabela": "aluno", ...}
M4  catálogo             aluno começa na página 2, registro de 28 bytes
M2  cache de páginas     entrega as páginas da corrente, da memória ou do disco
M1  página e arquivo     lê 4096 bytes no deslocamento certo
M4  execução            desserializa cada slot e imprime 1|20260001|Ana

M3  árvore B+            ainda parada. Quem decide usar o índice é o M5

O parser não sabe o que é página, e o cache não sabe o que é SQL. Cada módulo só usa o que vem antes dele.

Injeção de SQL

Por que concatenar string quebra, e parâmetro não?

# concatenação: o texto do usuário vira gramática
sql = "SELECT * FROM aluno WHERE nome = '" + nome + "'"
# nome = x' OR '1'='1    →  devolve a tabela inteira

# parâmetro: o texto do usuário nunca passa pelo parser
banco.execute("SELECT * FROM aluno WHERE nome = ?", (nome,))
# nome = x' OR '1'='1    →  devolve nada

Rodem agora: python3 injecao.py, em /assets/code/bd2-2026/. Só precisa do Python.

O que o tokenizador vê

Com nome = Ana:

SELECTpalavra*símboloFROMpalavraalunonomeWHEREpalavranomenome=símbolo'Ana'textoFIMfim

Com nome = x' OR '1'='1:

SELECTpalavra*símboloFROMpalavraalunonomeWHEREpalavranomenome=símbolo'x'textoORpalavra'1'texto=símbolo'1'textoFIMfim

O usuário deveria entregar um token. Entregou cinco, e um deles é palavra reservada. A árvore mudou de forma.

Parâmetro: um buraco na árvore

SELECT * FROM aluno WHERE nome = ?

  • A consulta é tokenizada e analisada antes de o valor existir
  • O valor entra depois, já como folha, qualquer que seja o conteúdo
  • x' OR '1'='1 vira só um nome estranho, que não bate com aluno nenhum

Escapar aspas à mão é a defesa errada: basta esquecer um caso. Em inglês, prepared statement.

O catálogo também é tabela, e também vaza

$ python3 injecao.py "x' UNION SELECT 0, sql, 0 FROM sqlite_schema --"
concatenado: SELECT * FROM aluno WHERE nome = 'x' UNION SELECT 0, sql, 0 FROM sqlite_schema --'
  devolveu: [(0, 'CREATE TABLE aluno (id INT, nome TEXT, nota INT)', 0)]
  • O -- transforma a aspa que sobrou em comentário
  • O UNION junta uma consulta inteira, escolhida pelo atacante
  • Como o catálogo é consultável com SQL, o primeiro passo do ataque é ler o catálogo e descobrir o nome das outras tabelas

A lição do módulo

O parser decide o que é comando e o que é dado. Concatenar string apaga essa fronteira, e é por isso que a injeção existe.

Quem implementou um parser não esquece mais essa distinção. É o motivo de segurança ser ensinada aqui, e não numa aula separada.

Apêndice

O esqueleto do M4: o parser

class Parser:
    def __init__(self, tokens):
        self.tokens, self.i = tokens, 0
    def olha(self):
        return self.tokens[self.i]
    def aceita(self, tipo, valor):
        if self.tokens[self.i] == (tipo, valor):
            self.i += 1
            return True
        return False
    def espera(self, tipo, valor=None):
        t, v = self.tokens[self.i]
        if t != tipo or (valor is not None and v != valor):
            raise ErroSintatico(f"esperava {valor or tipo}, veio {v!r}")
        self.i += 1
        return v
    def valor(self):
        t, v = self.olha()
        if t in ("NUMERO", "TEXTO"):
            self.i += 1
            return v
        raise ErroSintatico(f"esperava valor, veio {v!r}")

    def comando(self):
        _, v = self.olha()
        if v == "CREATE":   arvore = self.create()
        elif v == "INSERT": arvore = self.insert()

    def create(self):

        self.espera("PALAVRA", "TABLE")
        tabela = self.espera("NOME")
        self.espera("SIMBOLO", "(")
        colunas = [self.coluna()]
        while self.aceita("SIMBOLO", ","):
            colunas.append(self.coluna())
        self.espera("SIMBOLO", ")")

O esqueleto do M4: colunas e tipos

    def coluna(self):                     # devolve (nome, tipo, tamanho em bytes)
        nome = self.espera("NOME")
        if self.aceita("PALAVRA", "INT"):
            return (nome, "INT", 4)
        self.espera("PALAVRA", "CHAR")
        self.espera("SIMBOLO", "(")
        n = self.espera("NUMERO")
        self.espera("SIMBOLO", ")")
        return (nome, "CHAR", n)

def confere_tipos(esquema, valores):      # semântica do INSERT, fora do parser
    if len(valores) != len(esquema.colunas):
        raise ErroSemantico(f"esperava {len(esquema.colunas)} valores, vieram {len(valores)}")
    for (nome, tipo, n), v in zip(esquema.colunas, valores):
        if tipo == "INT" and not isinstance(v, int):
            raise ErroSemantico(f"coluna {nome} é INT, veio {v!r}")
        if tipo == "CHAR" and not (isinstance(v, str) and len(v.encode()) <= n):
            raise ErroSemantico(f"coluna {nome} é CHAR({n}), veio {v!r}")

O insert segue o mesmo molde do create, trocando coluna por valor.
